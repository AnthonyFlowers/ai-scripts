# lb-relations

Convert **LoopBack 3 model relations** into **TypeORM relation decorators**
for NestJS 12.

`lb2nest.py` (in `../loopback-to-nest/`) scaffolds a whole NestJS app from a
LoopBack 3 codebase, but it deliberately emits relations only as
`// wire this up by hand` comments — deciding the owning side, the foreign
key, and the inverse-side property is the fiddly part. `lb_relations.py`
fills that gap.

It reads **every** model in the app (so it can see both ends of each
relation), pairs them up, and emits per model a TypeScript fragment of
relation properties with the correct decorators, imports, and inverse-side
arrow functions `() => OtherEntity`.

Python 3.9+, no dependencies. It emits TypeScript; nothing here runs Node.

## Mapping

| LoopBack 3 | TypeORM | Notes |
|------------|---------|-------|
| `belongsTo` | `@ManyToOne` + `@JoinColumn` | owning side, holds the FK |
| `belongsTo` (paired with a `hasOne`) | `@OneToOne` + `@JoinColumn` | owning side, holds the FK |
| `hasMany` | `@OneToMany` | inverse side (needs the `@ManyToOne` counterpart) |
| `hasMany` + `through` | `@ManyToMany` + `@JoinTable` | junction table; `foreignKey`/`keyThrough` become join columns |
| `hasOne` | `@OneToOne` | inverse side; the FK-holding side gets `@JoinColumn` |
| `hasAndBelongsToMany` | `@ManyToMany` + `@JoinTable` | implicit junction table |
| `referencesMany` | array-of-ids `@Column` | no native TypeORM equivalent — flagged |
| `embedsOne` | `@Column(() => Type)` | embedded entity — flagged |
| `embedsMany` | JSON `@Column` (array) | embedded entities can't be arrays — flagged |

Pairing rules:

- The **inverse-side property name** (the `x => x.foo` in each arrow function)
  is looked up from the matching relation on the *other* model — a `belongsTo`
  is paired with the target's `hasMany`/`hasOne` by matching model + resolved
  foreign key, and vice versa.
- For a many-to-many, `@JoinTable` is placed on **exactly one** (owning) side —
  deterministically the lexicographically-smaller entity name — and the other
  side is emitted inverse-only, matching TypeORM's rule that `@JoinTable` must
  appear on a single side.
- LoopBack's default foreign keys are applied when omitted: `belongsTo` uses
  `camelCase(relationName) + 'Id'`; `hasOne`/`hasMany` use
  `camelCase(sourceModel) + 'Id'` (the FK lives on the target).

Relations with no clean mapping — `referencesMany`, `embedsOne`/`embedsMany`,
polymorphic, self-referential, or a `@OneToMany` with no matching inverse — are
still emitted best-effort **and** collected into a "needs manual attention"
report.

## Usage

```sh
# print snippets + the manual-attention report (default)
./lb_relations.py path/to/loopback-app

# just the report
./lb_relations.py path/to/loopback-app --report-only

# write the printed output to a file
./lb_relations.py path/to/loopback-app -o relations.txt --to-file

# write per-model <model>.relations.ts files (+ RELATIONS.md) into a dir
./lb_relations.py path/to/loopback-app --out ./rel-out
./lb_relations.py path/to/loopback-app --out ./rel-out --dry-run
./lb_relations.py path/to/loopback-app --out ./rel-out --force

# a single model file (pairing is limited — only one model is visible)
./lb_relations.py path/to/models/order.json
```

The input may be a LoopBack app root (models discovered under `common/models`,
`server/models`, or `models`), a models directory, or a single model `.json`.
A model's relations live in its `relations` key, each
`{ type, model, foreignKey, through, keyThrough, primaryKey, polymorphic }`.

### Output shape

Each fragment is a self-contained, valid-TypeScript
`export class <Model>Relations { … }` carrying the decorated relation
properties. Merge the property block into the model's `*.entity.ts` (as
generated by `lb2nest.py`) and fold the emitted imports into the entity's
existing import statements. Entity import paths follow lb2nest's layout
(`../<model>/<model>.entity`).

When writing to a directory, it refuses to overwrite a non-empty directory
without `--force`, and `--dry-run` lists the files without writing them —
matching `lb2nest.py`.

## Tests

```sh
python3 lb-relations/test_lb_relations.py
```

The tests build a small LoopBack app in a temp dir (a `belongsTo`/`hasMany`
pair, a `hasAndBelongsToMany` pair, a `hasMany`-through, a `hasOne`, plus
`referencesMany`/`embeds` cases) and assert the generated decorators,
imports, inverse property names, single-side `@JoinTable` placement, and the
directory-write overwrite guard. No third-party dependencies.
