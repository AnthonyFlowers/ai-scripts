# Script recommendations

Candidate scripts to build next, ordered by expected usefulness. The goal
driving the ordering: **reduce LLM token spend at work** by taking
deterministic work away from the model, shrinking what enters the context
window, and spending the cheapest tokens when tokens must be spent.

Already built: `token-report` (find where the tokens go) and `ctx-pack`
(shrink pastes before they hit the context window), each shipped as both a
zero-dep Python script and a TypeScript (`npx tsx`) port. Everything below
is ranked assuming those two exist. New scripts should default to
TypeScript, and the code-aware ones should understand the work stack:
**LoopBack 4 + TypeScript** (`@loopback/*`, `*.model.ts` /
`*.repository.ts` / `*.controller.ts`).

## 1. `repo-brief` — cached codebase summary

Generate a compact summary of a repo (file tree with per-file one-liners,
public API signatures only, no function bodies) and cache it, regenerating
on commit. Paste it at the start of a session instead of letting the agent
Glob/Grep/Read its way to the same understanding every time. For the work
repo, make it LoopBack 4-aware: list controllers with their route
decorators, models with their properties, and repositories, since that's
the map an agent actually needs.

*Why first:* exploration is re-done in every conversation and is usually the
second-biggest token sink after raw pastes. A brief regenerated by a git
hook amortizes that cost to zero. Pairs directly with what `token-report`
will show for long-lived projects (high cache-read, many calls).

## 2. `session-mine` — harvest repeated agent work into scripts

Scan Claude Code transcripts (`~/.claude/projects/**/*.jsonl`) for repeated
tool-call sequences — the same grep/build/deploy patterns requested more
than twice — and flag them as candidates to freeze into shell scripts.

*Why here:* it's the meta-version of the MCP generators: anything asked of
an agent three times identically should become a script that costs nothing.
It systematically finds the next ten scripts for this list. Reuses the
transcript-parsing code already written for `token-report`.

## 3. `diff-brief` — minimal review context for PRs

Emit a PR/branch diff plus only the enclosing signatures (function/class
headers) of what it touches, instead of whole files. Feed *that* to a
review prompt.

*Why:* code review is a frequent, recurring LLM task and "read these 8
files" is its most expensive form. Cheap to build with `git diff` +
lightweight signature extraction; the TypeScript compiler API (or a regex
pass over `*.ts`) gives the enclosing signatures for a LoopBack 4 codebase.

## 4. `mcp-diff` — detect server drift

Snapshot a server's tools/resources/prompts (build on `mcp-curl --json`)
and diff two snapshots or a snapshot against the live server. Runnable in
cron/CI.

*Why:* every generated client/CLI in this repo silently goes stale when the
server changes; today discovering that costs an agent debugging session.

## 5. `mcp-regen` — regenerate all generated artifacts

A wrapper that re-runs the right generator (`mcp-gen-client` /
`mcp-gen-cli`) for every generated file, from a small manifest or by
parsing each generated file's header, then shows the git diff.

*Why:* with `mcp-diff` it turns "the server changed, ask Claude to update
the client" (an agent session) into a zero-token `git commit`. Ranked after
`mcp-diff` only because drift detection is what makes regeneration timely.

## 6. `llm-cache` — disk cache for scripted API calls

Wrapper for direct Claude API calls made from scripts: hash
(model, system, prompt) → cache the response on disk with a TTL.

*Why:* for classification/extraction jobs re-run over overlapping data,
repeat inputs become free. Stdlib-only, matches the repo's no-deps
convention. Only valuable if/when scripts here make direct API calls —
hence below the always-applicable items above.

## 7. `llm-route` — cheapest-model-first dispatch

For batch API jobs: try the cheapest capable model first, validate the
output mechanically (schema/regex/whatever the task allows), escalate to a
bigger model only on failure.

*Why:* typically a 5–10× cost cut on batch extraction/classification.
Natural sibling of `llm-cache`; same caveat about needing direct API usage.

## 8. `mcp-registry` — named server configs

A small config file (name → URL/transport/header env vars) plus a resolver,
so every MCP tool here takes `work-jira` instead of a URL + bearer flags.

*Why:* saves typing and mistakes daily, but saves engineering friction
rather than tokens.

## 9. `bin/check-sync.sh` — shared-code drift checker

Extract the marker-delimited transport regions duplicated across
`mcp-curl`, `mcp-gen-client`, and `mcp-gen-cli` and diff them; fail if they
diverge.

*Why:* protects the toolchain everything above builds on. Nearly free to
write; ranked here only because it saves maintenance pain, not tokens.

## 10. Cross-tool smoke test

Spin up `@modelcontextprotocol/server-everything` and run each MCP tool
against it end-to-end (all three READMEs already use it as the example).

*Why:* regression safety for the generators; same "engineering time, not
tokens" caveat.

## 11. `mcp-gen-docs` — Markdown reference docs from a server

Same introspection as `mcp-curl`, formatted as wiki-ready Markdown (tool
tables, schemas, example invocations).

*Why:* the artifact non-engineers can consume; nice-to-have.

## 12. `mcp-doctor` — server health/conformance checker

Handshake latency, negotiated protocol version, pagination correctness,
schema validity, well-formed errors on placeholder calls.

*Why:* useful when a server misbehaves, idle otherwise.

## 13. `mcp-mock` — serve a snapshot as a fake server

Take an `mcp-curl --json` snapshot and serve it with canned responses, for
offline testing of generated clients and of the generators themselves.

*Why:* the most speculative — build it when the smoke test (#10) needs a
stable offline target.
